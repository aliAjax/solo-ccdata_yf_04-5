# 冷链审计台（Cold Chain Audit Desk）

纯前端、**完全离线、无后端**的样本流转与冷链审计工具。直接打开 `index.html`（或 `npm run dev` / `npm run build`）即可使用，全部数据仅保存在浏览器 localStorage，可导出 JSON 事件流归档或换机导入。

## 能做什么

- **登记样本批次与分装管**：编号、类型（母管批次 / 独立分装）、初始量与单位、温区（超低温 / 深冻 / 冷藏 / 常温）、接收经手人、位置、温度、时间。
- **状态机受控流转**：已接收 → 在库 ↔ 转运中 → 检测中 → 隔离 → 已放行 → 已耗尽 / 已销毁。每个操作只列出当前状态下的合法跳转，非法跳转在事件派发层被拒绝；耗尽、销毁为终态。
- **分装（拆分）**：记录数量与每管量，**分装总量不得超过母管剩余量**，否则拒绝；取尽时母管自动耗尽。子管独立编号，保留父子谱系，可多级分装。
- **合并**：仅允许同单位、同温区的在制样本合并，按余量比例扣减，来源取尽自动耗尽，合并管保留多父谱系。
- **冷链交接**：每次入库 / 发运 / 到达退回都记录经手人、位置、温度、时间。温度超出样本温区时，该次跳转被拒绝，**当前样本与全部在制下游分装立即联动隔离**（已耗尽 / 已销毁的终态后代不联动）。
- **隔离处置**：未登记处置决定（批准使用回库 / 拒收报废销毁，含经手人、位置、当前温度、依据）前，隔离样本不能放行；处置通过后才能回库并继续放行流程。
- **追溯**：每个样本可看父子谱系树（可点击跳转）、剩余量 / 初始量、直接来源与全部只追加历史。
- **审计记录页**：按事件类型 / 关键词筛选全部交接；每条事件带 FNV-1a **哈希链**（`prev/hash`），并由独立存储锚点（条数 + 链尾哈希）兜底检测链尾删除或回滚。任何对历史的修改、删除都会在校验时被发现。
- **键盘与手机**：表单全部可键盘操作（<kbd>/</kbd> 聚焦搜索、<kbd>N</kbd> 聚焦登记、<kbd>Esc</kbd> 关闭弹窗，数字字段调起数字键盘）；响应式布局，手机端顺序为台账 → 操作 → 追溯 → 登记。

## 数据与可信模型

- 事件溯源：样本当前状态、剩余量、谱系均由事件流重放得到，UI 不保存可变业务状态。
- 事件只可追加；没有任何编辑或删除历史的入口。
- 导出的 JSON 即完整事件流；导入前强制校验哈希链与锚点，断裂文件拒绝导入。
